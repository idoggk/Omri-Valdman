# Brain Gains – אתר תרגול למבחן, מתמטיקה ופיזיקה (3–5 יח״ל)

Live site: https://idoggk.github.io/Omri-Valdman/

אתר סטטי לגמרי: HTML + CSS + מודולי JavaScript. אין שלב build, אין תלויות npm, ואין שימוש ברשת בזמן ריצה. עובד בטלפון וב-GitHub Pages.

## הרצה מקומית

דרוש Node.js (גרסה 18 ומעלה) בלבד:

```
node tools/serve.mjs          # http://localhost:8080/
node tools/serve.mjs 3000     # פורט אחר
```

שרת מקומי נדרש כי הדף טוען את `data/*.json` באמצעות `fetch` (לא עובד מ-`file://`).

## בדיקות

```
node --test
```

הבדיקות בודקות את `js/check.js` (פענוח תשובות), `js/answersets.js` (התאמת פתרונות מרובים ללא סדר), `js/progress.js` (מצב התקדמות ותוצאות), `js/sanitize.js` (ניקוי SVG) ו-`js/bidi.js` (בידוד טווחי מספרים).

## פרסום ב-GitHub Pages

Settings → Pages → Deploy from a branch → `main` / root. כל הנתיבים יחסיים, ולכן זה עובד גם תחת `/שם-המאגר/`.

## מבנה

- `index.html`, `styles.css` – מעטפת העמוד (עברית, RTL, מובייל קודם, מצב בהיר/כהה לפי המכשיר).
- `js/app.js` – ניווט (hash), תצוגות, אינטראקציה.
- `js/check.js` – פענוח ובדיקת תשובות (פונקציות טהורות).
- `js/store.js` – שמירת התקדמות ב-`localStorage` (עם try/catch); מיגרציה אוטומטית מהפורמט הישן.
- `js/progress.js` – לוגיקת התקדמות טהורה: תוצאה אחרונה לכל תרגיל, תור חזרה על טעויות.
- `js/answersets.js` – בדיקת תרגילים עם כמה פתרונות.
- `js/sanitize.js` – ניקוי מחרוזות SVG (בלי סקריפטים, `on*`, קישורי `javascript:`).
- `js/bidi.js` – בידוד טווחי מספרים (3–5) בתוך טקסט עברי.
- `data/math.json`, `data/physics.json` – התרגילים.

קישורים לשיתוף: `#/topic/math-3`, `#/ex/math-3-001`.

## הוספת תרגילים

מוסיפים אובייקט למערך בקובץ `data/math.json` (נושאים `math-3`, `math-4`) או `data/physics.json` (נושאים `phys-vertical`, `phys-horizontal`):

```json
{
  "id": "math-3-002",
  "topic": "math-3",
  "level": 1,
  "title": "כותרת בעברית",
  "statement": "טקסט HTML בעברית. ביטוי מתמטי: <span dir=\"ltr\">x + y = 3</span>",
  "inputs": [
    { "label": "x", "unit": "", "answer": "3/2", "tolerance": 0.01 }
  ],
  "tips": ["רמז כללי", "צעד ראשון", "כמעט התשובה"],
  "solution": ["צעד 1", "צעד 2"]
}
```

- `id` ייחודי; התקדמות נשמרת לפיו. אל תשנו מזהה של תרגיל קיים.
- `level`: 1, 2 או 3. `topic`: אחד מארבעת הנושאים.
- `answer`: מספר או מחרוזת (`"3/2"`, `"-0.5"`). `tolerance` הוא סטייה מוחלטת (ברירת מחדל 0.01).
- תרגיל בחירה (למשל "אין פתרון"): במקום `inputs` שמים `"choice": {"options": ["...", "..."], "correct": 1}` (האינדקס מתחיל מ-0).
- `statement`, `tips`, `solution` הם HTML מהימן (מותר `<br>`, `<sub>`, `<sup>`, `<span dir="ltr">`). ביטויים מתמטיים תמיד בתוך `<span dir="ltr">`.
- השדה `verify` מתעלמים ממנו באתר.
- בפיזיקה מניחים `g = 10 מ/ש²`, וכל יחידות המידה בעברית כמו בספרי הלימוד בישראל (מ', ש', מ/ש, מ/ש², ק"מ/ש) – גם בשדה `unit`, גם בניסוח וגם בפתרון.
- כל תשובה היא מספר ממשי: שלם או עשרוני סופי עד 2 ספרות אחרי הנקודה (בלי מספרים מרוכבים ובלי שברים מחזוריים).
- הרמז השלישי הוא רמז כמעט-תשובה: הוא לא מכיל את הערך המבוקש. `node tools/verify-physics.mjs` בודק זאת, וכן את נכונות התשובות.
- מזהי התרגילים רצים מ-001 בכל נושא ונשארים קבועים (המזהה הוא מפתח ההתקדמות); תרגיל חדש מקבל את המספר הבא.

## שדה `diagram` (איור)

שדה אופציונלי: מחרוזת SVG מוטמעת (נתונים שלנו). מוצג בעמוד התרגיל בין השאלה לשדות התשובה בתוך `<figure role="img">` עם `aria-label` מכותרת התרגיל. האיור מתכווץ לרוחב המסך (`max-width: 100%`) ומוצג על לוח בהיר גם במצב כהה, כך שקווים כהים (או `currentColor`) נשארים נראים. לפני ההצגה מוסרים `<script>`, מאפייני `on*=`, `<style>` (על תוכנו, כולל `@import`/`url(...)`), `foreignObject`/`iframe`/`animate` וקישורים שאינם `#...`. מחרוזת שאינה `<svg>...</svg>` תקין לא תוצג.

```json
"diagram": "<svg viewBox=\"0 0 100 50\" xmlns=\"http://www.w3.org/2000/svg\"><line x1=\"0\" y1=\"45\" x2=\"100\" y2=\"45\" stroke=\"currentColor\"/></svg>"
```

## שדה `answerSets` (כמה פתרונות)

שדה אופציונלי שבא **במקום** `inputs` כשלמערכת יש כמה פתרונות (למשל מערכת ריבועית):

```json
"answerSets": { "labels": ["x", "y"], "count": 2, "sets": [["2", "3"], ["-1", "0.5"]], "tolerance": 0.01 }
```

- `labels` – שמות הנעלמים (שדה קלט אחד לכל שם). `sets` – הפתרונות הצפויים, כל אחד מערך באורך `labels` (מספרים או שברים כמחרוזות). `count` – מספר השורות המוצגות (`count >= sets.length`; אפשר 1, 3, 4...). `tolerance` – סטייה מוחלטת (ברירת מחדל 0.01).
- השורות נקראות 'פתרון 1', 'פתרון 2'... אפשר להשאיר שורות ריקות. הבדיקה אינה תלויה בסדר השורות; שורה כפולה נספרת פעם אחת. התרגיל נפתר כשנמצאו כל הפתרונות הצפויים ואין שורה שגויה.
- המשוב אומר כמה פתרונות נכונים ואילו שורות נראות שגויות, בלי לחשוף ערכים. בלוק `choice` לצד `answerSets` מתעלמים ממנו.

## תוצאות וחזרה על טעויות

לכל תרגיל נשמרת תוצאת הניסיון האחרון שהושלם: `alone` (נכון, בלי רמזים ובלי פתרון), `hinted` (נכון אחרי רמזים), `review` (הוצג פתרון לפני תשובה נכונה, או ויתור), עם מספר ניסיונות וחותמת זמן. בדף הבית כרטיס 'חזרה על טעויות' מציג את התרגילים `hinted`/`review` (הישנים ראשונים), וכפתור 'התחל חזרה' עובר עליהם אחד אחד; תרגיל יוצא מהתור כשנפתר לבד. ברשימות הנושאים יש אייקון לכל תוצאה ומקרא. ההתקדמות נשמרת תחת המפתח `omri-study-progress-v2`; התקדמות ישנה (`v1`) מומרת אוטומטית.

## עברית ומספרים (bidi)

טווחי מספרים בתוך טקסט עברי (כמו 3–5) עטופים באיזולט LTR (`js/bidi.js`, ובכותרת `<bdi dir="ltr">`) כדי שלא יוצגו הפוך. כותרות תרגילים (ברשימה, בכותרת העמוד ובכותרת המסמך) עוברות דרך `isolateTitle`: כל רצף לטיני/נוסחה (`x² + y²`, `v = 10 m/s`) עטוף באיזולט LTR.

## Brain Gains

שם האפליקציה הוא **Brain Gains** (manifest, כותרת, `apple-mobile-web-app-title`, כפתור השיתוף, סיומת כותרת הדף). כל הטקסטים בממשק נשארים בעברית.

## מצב מבחן

כרטיס 'מצב מבחן' בדף הבית (`#/exam`): בחירת נושאים, 5/8/12 שאלות, קשה/מעורב, זמן (ברירת מחדל 6 דקות לשאלה, אפשר 'ללא הגבלה'). הסט נבנה אקראי עם seed, בלי חזרות, ומעדיף תרגילים שלא נפתרו לבד. במבחן: שאלה אחת בכל פעם, שעון, נקודות התקדמות, בלי רמזים/פתרון/משוב; הקודם, הבא, דלג, סיום (אישור בתוך הדף). המבחן הרץ נשמר ב-`localStorage` (`omri-study-exam-v1`) וממשיך אחרי רענון. הדוח: ציון, זמן, פירוט לפי נושא, כל שאלה עם התשובה הנכונה וכפתור 'הצג פתרון', והמלצה מה לתרגל. כל תוצאה נכנסת ל-`progress`: נכון = `alone`, שגוי או דולג = `review`. הלוגיקה הטהורה ב-`js/exam.js` (נבדקת ב-`tests/exam.test.mjs`).

## דף נוסחאות, דוגמאות פתורות ופתרון מודרך

הקבצים `data/formulas.json` ו-`data/examples.json` אופציונליים: אם חסרים או ריקים מוצגת הודעה 'יתווסף בקרוב' (ו-`sw.js` מטמן אותם עם `allSettled`). ה-HTML בהם עובר `sanitizeHtml` (תגיות `span sup sub b strong i em br code small bdi`, ורק התכונה `dir`).

`data/formulas.json`:

```json
{"topics": {"math-3": {"title": "...", "sections": [{"heading": "...", "items": [{"label": "...", "formula": "HTML", "note": "..."}]}], "mistakes": ["טעות נפוצה"]}}}
```

מפתחות הנושאים: `math-3`, `math-4`, `phys-vertical`, `phys-horizontal`. הדף נפתח כחלון בתוך העמוד מהדף הראשי, מכל דף נושא וכל דף תרגיל (הנושא הנוכחי ראשון); 'טעויות נפוצות' מתקפל.

`data/examples.json` (מערך):

```json
[{"id": "ex-math-3-elim", "topic": "math-3", "title": "...", "problem": "HTML", "steps": ["HTML"], "takeaway": "..."}]
```

מוצגות בדף הנושא תחת 'דוגמאות פתורות': אחת פתוחה בכל פעם, הצעדים נחשפים בלחיצה על 'הצעד הבא'.

שדה אופציונלי בתרגיל, `guided` (3–6 צעדים):

```json
"guided": [{"q": "מה הצעד הראשון?", "options": ["...", "...", "..."], "correct": 0, "explain": "למה", "wrongExplain": ["למה אפשרות 1 שגויה"]}]
```

כפתור 'פתרו אותי צעד צעד' פותח מדריך: שאלה בכל פעם, משוב והסבר מיידיים. סיום המדריך לא נחשב כפתרון; פתיחתו מסמנת `guided` בהתקדמות, והתרגיל ייחשב `hinted` לכל היותר. הלוגיקה ב-`js/guided.js`.

## Add to home screen (הוספה למסך הבית)

- הוספת **Brain Gains** למסך הבית:
- **iPhone (Safari):** כפתור השיתוף בתחתית ← ״הוסף למסך הבית״ ← ״הוסף״.
- **Android (Chrome):** תפריט ← ״התקן אפליקציה״ / ״הוסף למסך הבית״ (או הכפתור ״התקן״ באתר).
- האתר נשמר במטמון (`sw.js`) ועובד גם בלי אינטרנט; כשמחוברים מקבלים תרגילים חדשים. בעדכון יופיע פס ״יש גרסה חדשה – רענן״.
- כשמוסיפים קובץ JS/נתונים חדש לאתר: להוסיף אותו לרשימת `PRECACHE` ב-`sw.js` ולהעלות את `CACHE_VERSION`.
- אייקונים: `node tools/make-icons.mjs`.

## עדכון גרסה

כל שינוי בקובץ שנמצא ב-`PRECACHE` של `sw.js` (קוד, נתונים, CSS, גופנים, אייקונים) דורש עדכון גרסה, אחרת מכשירים ישנים ימשיכו להציג את הקבצים מהמטמון.

1. `node tools/stamp-version.mjs` – מחשב גיבוב (hash) של כל קבצי ה-`PRECACHE` וכותב אותו ל-`BUILD_HASH` ב-`sw.js`. הכלי לא מעלה מספרי גרסה בעצמו.
2. מעלים ידנית את `CACHE_VERSION` ב-`sw.js`, את `APP_VERSION` ב-`js/pwa.js` ואת מספר הגרסה ב-`tests/sw.test.mjs` (שלושתם חייבים להיות שווים).
3. `node tools/stamp-version.mjs --check` בודק שהחתימה תואמת לקבצים (קוד יציאה 1 אם לא); גם הבדיקה `offline-hardening.test.mjs` נכשלת כשהחתימה לא עדכנית.

ההתקנה של ה-service worker אטומית: אם קובץ אחד לא ירד (אחרי ניסיון חוזר), הגרסה החדשה לא מופעלת והישנה ממשיכה לעבוד.

## Analyzing feedback

כלי לא-נשלח (לא חלק מהאתר) שמנתח את קובץ ה-JSON שיוצא ממסך המשוב:

```
node tools/analyze-feedback.mjs path/to/brain-gains-feedback-YYYY-MM-DD.json
```

הדוח (Markdown) מודפס למסך, והקובץ `content-overrides-proposal.json` נכתב ליד קובץ הקלט (או לתיקייה שב-`--out <dir>`). בדוח: קושי ממוצע לפי מיומנות/תבנית, אחוז תגי קושי, תרגילים שדורגו 9-10 שוב ושוב, מועמדים לתיקון (8-10 + שגוי) ולקידום (1-3 + נכון פעמיים), בטוח-אבל-שגוי (כשאין שדה `confident` ברשומה: קירוב של דירוג קל + שגוי) ו-5 יעדי תוכן הבאים. ההצעות הן רשימה לבדיקה ידנית בלבד; הכלי לא משנה תשובות או נתוני אפליקציה.
